That is correct for the common case, but it structurally cannot support a task whose entire objective is "fix and merge an existing, different PR's branch" (this task, and any future rebase-a-stale-PR task) -- the worker's auto-assigned branch is never the PR branch that needs fixing. Worth a PM decision on whether that's acceptable long-term or whether the hook should special-case this task shape (e.g. via a task.yaml field naming an explicit off-branch target).
